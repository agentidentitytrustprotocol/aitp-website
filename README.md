# AITP Website

Public-facing documentation website for the **Agent Identity & Trust Protocol (AITP)**.

- **Live site:** [agentidentitytrustprotocol.io](https://agentidentitytrustprotocol.io)
- **Framework:** [Next.js](https://nextjs.org) + [Fumadocs](https://fumadocs.vercel.app)
- **Content:** Synced from 5 source repos via GitHub Actions

## Getting Started

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

## Content Sync

Documentation is pulled from the AITP source repos (siblings under `../`) and
converted to MDX with frontmatter injection, code-aware tag escaping, and
internal-link rewriting.

**Manual sync:**

```bash
./scripts/sync-content.sh
```

`scripts/escape-mdx.py` performs the MDX-hostile-character escaping (placeholder
tags like `<identifier>`, numeric comparisons like `<43`, bare `{`/`}`, and
table-cell pipes inside code spans) while leaving fenced/inline code intact.

The sync also removes any synced page whose source file was deleted upstream
(`scripts/prune_synced.py`), and fails rather than prune if a source checkout
is missing or empty.

**Automated sync:** `.github/workflows/sync-docs.yml` runs on source-repo pushes
(via `repository_dispatch`), on a 6-hour schedule, or manually, and opens a PR
with the regenerated `content/`.

## Deployment

Deployed to Vercel as a **public** site at `agentidentitytrustprotocol.io`
(team `zer07labs`, project `aitp-website`). Vercel's Git integration builds
every push: `main` deploys Production, other branches deploy Preview (behind
Vercel authentication). Build command `next build`. No GitHub workflow deploys
and no Vercel token lives in GitHub.

### Configuration (Doppler)

Doppler is the source of truth for the site's deployment variables. The project
is `aitp-website`, with configs `dev` (local), `dev_personal` (your overrides),
`stg` and `prd` (Vercel Production).

The site is fully static and reads no variables today, so every config is empty
and [deploy/doppler-keys.txt](deploy/doppler-keys.txt) lists no keys. Locally,
`doppler setup --project aitp-website --config dev` once, then
`doppler run -- npm run dev` (plain `npm run dev` behaves the same while the
configs are empty).

To add or change a Production variable, set it in Doppler `aitp-website/prd`,
list its name in `deploy/doppler-keys.txt`, commit, then:

```bash
deploy/doppler-sync.sh           # dry run: key names and changed/unchanged, no values
deploy/doppler-sync.sh --apply   # push changed keys to Vercel Production, then rebuild it
```

The script manages only the listed keys, and only in Production. It never
removes a Vercel variable, never prints a value, refuses a dirty tree, refuses
`RAILWAY_*`/`VERCEL_*` names and Railway `${{ }}` reference values, and rebuilds
only when a value changed. **Preview is kept separate:** the script never reads
or writes Preview or Development, refuses a Production entry shared with them,
and Preview must never hold admin keys or passwords. Vercel holds no Doppler
token. A Vercel "sensitive" variable cannot be read back, so the script refuses
to compare it; verify such a key by behaviour instead.
